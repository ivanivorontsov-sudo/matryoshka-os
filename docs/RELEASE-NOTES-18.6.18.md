# Матрёшка 18.6.18

Пакет обновления `matryoshka-update-18.6.18.tar.gz` ставится поверх 18.6.3–18.6.17.2 тем же способом, что и раньше (копия, затем архив). Выпуск v18.6.17 и все его файлы оставлены.

## Вивальди: «Дешифровка прервана — не удалось разблокировать хранилище ключей»

Что было: Chromium и Вивальди на Linux помечают записи двумя способами. `v10` всегда зашифрованы ключом `peanuts`, `v11` — случайным ключом «Vivaldi Safe Storage» из бумажника. Перенос в 18.6.17 искал только `v10`, записи `v11` (а это все логины и куки, сохранённые при включённом бумажнике) считал «готовыми», ставил `--password-store=basic` и глушил бумажник. Вивальди не мог прочитать `v11` без бумажника и показывал окно «Дешифровка прервана».

Что сделано:

- записи `v11` перешифровываются в `v10` (`peanuts`) ключом из бумажника. `v10` Вивальди читает при любом хранилище, поэтому перенос ничего не теряет. Проверено на настоящем Chrome: кука, переведённая из `v11`, после переноса уходит на сайт;
- берутся ключи всех браузеров из бумажника (у Chrome и Вивальди они разные), ключ хранится в `~/.config/matryoshka/os-crypt-key` (0600) до конца переноса;
- перешифровка идёт только при закрытом Вивальди: иначе он может записать куки обратно старым ключом;
- перед изменением базы делается копия: `*.matryoshka-v11-backup` и `*.matryoshka-before-rekey` рядом с `Login Data` и `Cookies`;
- пока в профиле есть записи `v11`, а ключа нет, бумажник не глушится, флаг `basic` снимается, Вивальди работает со своим ключом как раньше. При входе паролем учётной записи бумажник открывается этим же паролем без окна, ключ забирается, Вивальди переносится, и бумажник выключается окончательно. После входа по лицу или отпечатку Вивальди один раз спросит пароль бумажника;
- при обратном включении бумажника ключ в нём больше не затирается, если в профиле остались записи `v11`.

> [!WARNING]
> Если окно «Дешифровка прервана» уже показывалось, закройте его крестиком. Жёлтую кнопку «Продолжить с потерей данных» не нажимайте: она стирает логины.

## Zoom

- Ссылка входа (Google, SSO: `zoommtg://zoom.us/google?code=…`, `zoomprc://…`) больше не отправляется повторно. Раньше `zoom-run` при быстром выходе `ZoomLauncher` (а он выходит сразу, когда передаёт ссылку уже запущенному клиенту) запускал её второй раз. Одноразовый код второй раз не принимается, вход не проходил. Повтор без GPU остался только для первого запуска клиента и встречи по номеру.
- Тот же повтор ставил метку `zoom-no-gpu` и переписывал `~/.config/zoomus.conf` на настоящей видеокарте. Испорченный или чужой `zoomus.conf` — известная причина ошибки 5003 и «Timeout» при входе на Linux. Теперь метка ставится только на виртуальной видеокарте; пустая метка 18.6.17 на настоящей видеокарте снимается; `zoomus.conf`, который переписала 18.6.17, один раз откладывается в `zoomus.conf.matryoshka-18.6.17`, и Zoom создаёт чистый. Правка `zoomus.conf` теперь побайтная, с копией `zoomus.conf.matryoshka-bak`.
- В сеансе Plasma на Wayland включается `enableWaylandShare=true` (демонстрация экрана через портал `xdg-desktop-portal-kde` и PipeWire). `pipewire-audio` (с `pipewire-pulse`), `wireplumber`, `pulseaudio-utils`, `xdg-desktop-portal-kde` в образе остаются.
- Проверено на тестовой конференции zoom.us/test (Zoom 7.2.5 (6661)): ссылка из Firefox → `zoom-open` → `ZoomLauncher` → клиент, вход в «Test Zoom Meeting» без ошибки.

Если 5003 остаётся: ошибка значит, что клиент не достучался до серверов Zoom.

## Wi-Fi при выключенном бумажнике

- Служебная проверка NetworkManager (`30-matryoshka-wifi-key`) при подключении возвращала сети без пароля в файле флаг «пароль у агента» (`psk-flags=1`). Теперь при выключенном бумажнике сети остаются системными (`psk-flags=0`), и ответ из окна пароля сразу пишется в файл соединения.

## Исходники

`matryoshka-src-18.6.18.tar.gz` — исходное дерево на коммите выпуска, без `.git`. Проверка: `sha256sum -c` по файлу `.sha256` рядом.
